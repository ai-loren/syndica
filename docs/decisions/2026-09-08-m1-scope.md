# 里程碑 1 剩余范围的裁决（子计划 2–6）

用户裁决时间：2026-09-08。这些决定约束计划 2–6 的全部范围，写计划时不得再重新解释。

## 1. 真 LLM provider

**放计划 4，建立第一个 backend 包，只做 OpenAI 兼容 HTTP。**

依据：spec §5.7 明确「内核不认识具体 provider，实现由 backend 注册」，所以真 provider 意味着建立第一个 backend 包——这也会第一次真正激活 §3.2 规则 5（backend 不得 import surface）与 `pip install syndica` 的零重依赖承诺。选 OpenAI 兼容协议是因为单个实现覆盖面最大（OpenAI、各类网关、vLLM、多数厂商的兼容端点），且里程碑 2 自举立刻能用。

Anthropic 原生等其他 provider 不在里程碑 1。

## 2. 内置工具范围

**文件 + 执行 + 编排三组都做。**

依据：里程碑 1 判据要求「Runtime 能创建多个 Agent、互发消息」。若编排类工具不进来，多 Agent 只是宿主代码的能力而非 Agent 的能力，Agent 自己派不了活，里程碑 2 自举时也无法委派。

**任务归属**：
- **编排工具（`Delegate` / `Fork` / `SendMessage` / `QueryAgent` / `KillAgent`）→ 计划 2**，它们是 Runtime 控制面方法的薄封装，控制面在哪它们就在哪。
- **文件与执行工具（`Read` / `Write` / `Edit` / `Glob` / `Grep` / `Bash` 及其 `BashOutput` / `KillBash`）→ 计划 4**，因为它们必须经 Portal 执行。

明确不在里程碑 1：`Terminal`（PTY，spec §15 归里程碑 5）、`TodoWrite` / `TaskGraph*`、`Deliver`（里程碑 7）、`GetBudget` / `Compact`（里程碑 8）、`Skill`、背景任务三件套。

## 3. 危险判定与人工确认

**计划 2 做纯规则的危险判定（输出规则 ID / 风险等级 / 原因），处置只实现「直接阻断」与「放行」两档；人工确认交互留给 CLI（计划 6）。**

依据：计划 2 的工具并发要求「需要人工授权的一律判为不安全」，所以并发分段必须能问出「这个调用要不要授权」；而里程碑 2 自举意味着框架开始对自己的代码跑 Bash，自举之前就该有一道闸。

按 spec §5.6，判定与处置必须分离：判定不读配置、不调 LLM、不决定交互方式。

## 4. 人在环

**计划 2 做 `wait_for` / `Waiter` 密封类型 / `WaitResult` 四态 与 `WAITING` 状态转换；`AskUser` / `AskUserQuestion` 工具留到计划 6 与 CLI 交互模式一起。**

依据：公开面一次成型（`wait_for` 是 §4.2 的 11 个公开方法之一，`WAITING` 是 §4.1 六态之一），而工具在没有交互界面时无处落地。

## 5. 流程严格度

**全程保持与计划 1 相同的全量严格**：每个任务走「实现 → 自我变异证伪 → 独立评审（评审自创变异）→ 修复 → 收口」。

依据：计划 1 的 14 轮里独立评审**每次**都找到实现者漏掉的东西，命中率 100%；而计划 2 与 4 触及并发、生命周期、子进程执行，恰恰是最容易留隐蔽缺陷的地方。

## 6. 计划产出节奏

**一个一个来**：写计划 2 → 执行到收口 → 写计划 3 → …

依据：spec §15 自己的理由——「计划按里程碑逐个产出，前一个完成后再写下一个，这样后面的计划能吸收前面的实际情况」。计划 1 的执行产出了 13 条写进 `AGENTS.md` 的教训，那些会改进后续计划的起草质量。

## 由此确定的子计划边界

| 子计划 | 范围 |
| --- | --- |
| **2** | 事件循环与 IDLE↔RUNNING 周期；`DEFERRED` 消费时机；`ensure_active` 与 `send` 的真实激活（`on_missing_queue` 接线）；`kill` / `despawn` / `pause` / `resume` / `abort`（含 `recursive`）；`WAITING` + `wait_for` + `Waiter` + `WaitResult`；危险判定（纯规则）+ 阻断/放行两档处置；工具并发分段（安全从严）；`agent.register_hook` 与 `Runtime(plugins=[...])`（§5.3 第一、二层）；编排工具五个 |
| **3** | 声明式 Agent 定义（§4.6，含清单十字段、加载与同名覆盖可查询、提示词插值白名单）；Topology 装配（§4.7，三档 cardinality、三档 boot、只增量增强的硬约束）；内核内置的四个 Agent（§4.8：`Orchestrator` 类式，`Planner` / `Explorer` / `Worker` 声明式） |

| **6** | CLI（§9.1 名词+动词、默认子命令 `run`、`chat` 是 `run --session` 的外壳、预算与 flag 的传参形态之分）；L2 声明式场景回放层（§13.1）；`AskUser` / `AskUserQuestion` 与人工确认交互 |

## 顺带确定的归属

- 台账里**目前无主**的「`unregister` 一个有子代的父会留下悬空 `parent_id`」→ **计划 2**，`despawn` / `kill --recursive` 是它的天然归属。
- 计划 1 遗留的「租约字段只能经无条件 `update` 写，真做孤儿回收需要原子操作」→ 仍留在里程碑 1 之后（孤儿回收不在 §15 里程碑 1 判据内）。

**Goal:** Syndica 与四个协议生态双向互通，且互通不绕过 Syndica 的会话、trace、溯源、脱敏与危险判定：

- **MCP**：Syndica 的 Agent 用外部 MCP server 的工具（client）；外部 MCP 客户端调用 Syndica 的工具、读产物、取角色提示
  （server，stdio 与 Streamable HTTP）。
- **ACP**（Zed 的 Agent Client Protocol）：编辑器等第三方客户端经 stdio 驱动 Syndica 的会话；Syndica 把第三方 ACP
  Agent（如 Gemini CLI）托管成一个角色，它的读写文件与终端由 Syndica 的工作区与安全层提供。
- **A2A**（v1.0，兼容 0.3）：外部 Agent 给 Syndica 派任务（agent card、任务、状态、流）；Syndica 把远端 A2A Agent 当成
  一个角色派活给它。
- **OpenAI 兼容 HTTP**：现有客户端经 `/v1/chat/completions` 与 `/v1/responses`（文本、function call、streaming）请求
  Syndica 的会话。

**Architecture:** 按 spec §3 的分层：**暴露 Syndica 的一侧是 surface，消费外部的一侧是 backend。** 四个「被调用」的
适配（MCP server、ACP agent、A2A server、OpenAI HTTP）都放进已有的 `syndica.server`：它们共用 M9 的 `Live`（待答表、
答复校验、无人值守）、外发脱敏出口、认证与会话装配，stdio 的两个入口（`syndica mcp`、`syndica acp`）与 `syndica up`
一样经组合根 `syndica/serve.py` 起。三个「调用外部」的适配各成一个 backend（`backends/mcp`、`backends/acp`、
`backends/a2a`），互不依赖：MCP 的外部工具包装成 Syndica `Tool`；托管的 ACP Agent 与远端 A2A Agent 包装成 **LLM
适配器**（角色的 `model: acp:<name>` / `model: a2a:<name>`）——外部 Agent 对 Syndica 而言就是一个「自己会用工具的
模型」：预算、截止时刻、trace 的模型调用 span、溯源（它的回答一律不可信）都沿用模型调用这条路。内核只加两处：一个
在 Agent 之外按同一套判定与处置执行一次工具调用的公开入口，和一种记外部 Agent 活动的事件。

**Tech Stack:** 官方 SDK 各进各的 extra（用户 2026-10-09 选定）：`syndica[mcp]` → `mcp>=2.3,<3`（MIT，27 个传递依赖，
两个协议时代都能服务）；`syndica[acp]` → `agent-client-protocol>=0.12,<0.13`（Apache-2.0，只依赖 pydantic）；
`syndica[a2a]` → `a2a-sdk[http-server]>=1.2,<2`（Apache-2.0，33 个，带 google-api-core / protobuf / requests）。
OpenAI 兼容 HTTP 不引 SDK，挂在 `syndica up` 的 Starlette app 上；`openai>=3.26,<4` 只进 `dev`，当一致性客户端。
各 SDK 也用作测试里对端的一致性实现。kernel 与 `pip install syndica` 的依赖不变。

## 现状（决定设计的事实）

内核与宿主：

1. **工具可以带运行时的 JSON schema**：`Tool.__tool_schema__` / `__tool_name__` 按实例属性读（回放的
   `_RecordedTool` 就这么做）；但 Module 装的工具必须在**自己的类上**声明 `__tool_command_args__` 元组
   （`require_own_command_args`），所以每个外部工具要按需生成一个子类。执行器**不按 schema 校验实参**（只要求
   是对象）。OpenAI backend 的 `_clean_schema` 遇到 `$ref` 抛错。
2. **没有 Agent 就没有工具的安全门**：判定（`DangerJudge.judge`）与处置（`disposition_of`）是公开的，但「判定 →
   处置 → 在不可信的调用信任下执行 → 记 trace」只在 `ToolExecutor` 里；设调用信任的 `_CALL_TRUST` 是私有的，宿主代码
   的写入因此记成**可信**（`WorkspaceRouter._write_trust()` 在工具调用之外取 TRUSTED）。
3. **LLM 适配器可以交回不可信的回答**：`BaseAgent._called` 之后只会把 `reply.trust` 收紧、不会放宽；`model:
   <平台>:<型号>` 由组合根 `_configured_model` 解析。LLM 协议没有流式。
4. **配置**：`FlagValue` 只有 bool / int / str，列表与映射要新的根键；`.syndica.yaml` 未识别的根键报错；信任摘要
   覆盖原文字节，`describe()` 决定人看到什么；`_refuse_export_settings` 已有「仓库配置不能指定接收你鉴权头的端点」
   的先例（OTLP）。
5. **Agent 环境**：白名单 + 宿主设定值 + `pass_env`（形似密钥的名字拒收、`GIT_*` / `GH_*` 等拒收），`SYNDICA_AGENT_ENV=1`
   标记；凡是执行工作区代码的子进程只在它里面跑。`syndica up` 的子进程用 `python -P`（M9 B-1）。
6. **没有可复用的长寿子进程监管**：`LocalWorkspace` 的进程组管理是私有的、只跑 shell、stdin 是 `/dev/null`。
7. **server**：`create_app` 没有挂额外路由的口子；最后一条是静态文件的兜底路由，新路由必须排在它前面；`_Guard` 对
   每个 http / websocket 作用域查 Host / Origin；令牌只在内存里，浏览器靠一次性登录码换。OpenAPI 快照的路径表必须
   等于 app 的路由表。`Live` 有待答表、答复校验（`approve` / `reject`、逐字选项）与无人值守（30 秒）。
8. **私有访问守卫**：`server/**` 不得访问 `._x`、不得 import 私有名字；写入点守卫认得 Starlette 响应、WebSocket 发送、
   子进程的 stdin（按内容判）与 `.send/.post/.request/.stream` 的正文。

SDK（实测，见调查报告的结论）：

9. **MCP 2.3.0**：低层 `Server` 一个对象同时服务 2026-07-28（无握手、每个请求带 `_meta`、`server/discover`）与
   ≤ 2025-11-25（`initialize`）；stdio 按第一个请求定时代，HTTP **只按 `MCP-Protocol-Version` 头**定。任意 schema 的工具
   只能用低层 API。Streamable HTTP 要在宿主 lifespan 里进 `session_manager.run()`（只能进一次）；自建的 manager 默认
   **不防 DNS rebinding**。旧时代下处理器抛出的异常以 `code: 0` 原文回给客户端；服务端不校验实参；HTTP 新时代每次
   `tools/call` 会重跑 `tools/list`（除非给 `get_tool_input_schema`）。客户端：`Client(mode='auto')` 先探
   `server/discover` 再退回 `initialize`；**stdio 子进程只继承 `HOME LOGNAME PATH SHELL TERM USER` 加传入的 `env`**，
   起在新会话组里，关闭时 stdin → 2 秒 → SIGTERM 组 → 2 秒 → SIGKILL；`read_timeout_seconds` 超时 -32001；新时代下
   服务端不能反向请求（采样 / 征询 / roots）。客户端默认开响应缓存。
10. **ACP 0.12.1**（协议版本 1，NDJSON over stdio）：Agent 侧是结构化 Protocol，`_meta` 的键会被摊进 kwargs；客户端
    `spawn_agent_process` 的子进程环境同样只有六个变量；**stderr 默认接管道且没人读，刷满就死锁**；**没有任何请求
    超时**；`session/cancel` 不会取消 Agent 的 `prompt()`；版本协商要应用自己比；缺终端回调时回 `null` 而不是
    method-not-found；入站消息各在自己的任务里处理（可乱序）；首次记错误时 `logging.exception` 会给根 logger 装
    handler；处理器异常以 `-32603` + `data.details=str(exc)` 回给对端。
11. **A2A 1.2.2**（v1.0，可开 0.3 兼容）：类型是 protobuf；路由是普通 Starlette `Route`（不要 lifespan）；v1.0 方法名是
    `SendMessage` / `SendStreamingMessage` / `GetTask` / `CancelTask`…，**必须带 `A2A-Version: 1.0` 头**，否则 -32009；
    **不做任何鉴权**；执行器的异常原文回给客户端；首个事件必须是 `Task` 或唯一一个 `Message`；客户端工厂自己建的
    httpx 只有 5 秒超时（流也算）；服务端错误是 `A2AError` 而不是 `A2AClientError`。agent card 的固定路径是
    `/.well-known/agent-card.json`。
12. **OpenAI 3.26.1**：README 已把 Responses（`/v1/responses`）当主接口，Chat Completions「无限期支持」；流式请求仍发
    `Accept: application/json`，服务端按请求体的 `"stream": true` 判；流是 `data: {...}` 加 `data: [DONE]`，usage 在
    `choices: []` 的最后一块；错误体 `{"error": {"message", "type", "param", "code"}}`；缺省重试 2 次（5xx 的 POST 会被
    重放）；`OPENAI_BASE_URL` / `OPENAI_CUSTOM_HEADERS` 环境变量会改写请求。

## 硬约束（沿用 + M10 特有，违反即打回）

1. **分层**：协议 SDK 不进 kernel（`check_deps` 把 `mcp`、`mcp_types`、`acp`、`a2a`、`openai` 加进 kernel 禁止的外部
   包）；`backends/mcp` / `backends/acp` / `backends/a2a` 互不依赖，只依赖 kernel；server 不 import backend——它要用的
   backend 能力（ACP 会话里客户端给的 MCP server）由组合根注入。缺 extra 时三件套指向 `pip install 'syndica[<名>]'`。
2. **外部内容一律不可信**（spec §12.2）：外部 MCP 工具的结果、外部 Agent（ACP / A2A）的回答与它在过程中产出的一切、
   协议客户端交来的工具结果，都以 `UNTRUSTED` 进轨迹；外部工具与外部 Agent 的描述文字（MCP 工具描述、agent card）
   不进 system prompt 之外的任何可信位置，长度封顶、去掉控制字符。没有「声明为可信」的捷径——要信任就别经协议接。
3. **外部发起的调用走同一套判定与处置**：经 MCP server 调 Syndica 工具、托管的 ACP Agent 请求读写文件与开终端，都经
   内核的同一个入口（见公开契约）判定、处置、执行、记 trace；调用方是外部模型，溯源按**不可信**算，所以高风险操作
   按 `untrusted_high_risk`（缺省拒绝）处置；开发模式的无条件拦截（git 写、删工作区根）照样生效；外部发起的写入在
   文件污点里记成不可信。
4. **密钥只从用户级配置来**（用户 2026-10-09 选定）：外部进程（托管的 ACP Agent、stdio MCP server）一律起在 Agent
   环境里；要额外透传的宿主环境变量、要发给远端（HTTP MCP server、A2A Agent）的鉴权头，只能写在**工作区之外**的
   用户级配置 `interop.yaml`（与信任存储同目录）里，按外部对象的名字列出；项目的 `.syndica.yaml` 只能按名字引用
   外部对象，点名任何形似密钥的变量都三件套拒收。这是硬约束 7 对「外部 Agent 进程本身」的唯一例外，范围只到用户在
   用户级配置里点名的那几个变量，文档写明后果（那个第三方进程看得见它们）。
5. **外部进程不留**：每个外部进程起在自己的进程组里；会话关闭、Runtime 关机、`down`、Ctrl-C 之后整组不在（用例在
   每条路径上查进程表，含孙进程）；子进程的 stderr 一律有人读（经脱敏写进日志，有上限），不接没人读的管道。
6. **每个出口都脱敏且不回显原始异常**：协议响应（JSON-RPC result / error、SSE、stdout 上的 NDJSON、OpenAI 错误体）
   只经 server 的外发序列化函数交出；四个 SDK 默认把处理器异常原文回给对端，适配层必须自己接住每一个异常、换成
   三件套（或协议等价字段）——用例对每个协议各注入一个带密钥原文的异常，断言对端收到的不含它。
7. **错误映射保留三件套**：JSON-RPC 错误 `data = {"expected","received","next_action"}`、`message` 是三件套连成的一句；
   OpenAI 错误体的 `message` 同理、`type` / `code` 按 OpenAI 的取值；A2A 失败状态的消息、ACP 的 `RequestError.data`、
   MCP 的 `isError` 工具结果都带三件套。
8. **版本协商失败不回退到未知行为**：MCP 只认 SDK 声明的五个版本、ACP 只认 1、A2A 只认 1.0 与 0.3；对端给别的就按协议
   规定的错误拒绝（MCP -32022 带 `supported`、ACP 返回自己支持的版本后由我们比对、A2A -32009），客户端侧协商出意外
   版本就三件套报错，不猜。
9. **只监听本机、凭证不落盘**（沿用 M9 硬约束 2–4）：HTTP 侧的协议路由挂在 `syndica up` 的同一个 app 上，同一个
   `_Guard`（Host / Origin）、同一个 `Credentials`；机器客户端的令牌由 `syndica up --api-token` 打印在人的终端上一次，
   只在 server 内存里，重启即失效（用户 2026-10-09 选定）。agent card 是唯一新增的公开路由（只含角色名与描述，
   不含任何会话内容）。`syndica mcp` / `syndica acp` / `--api-token` 在 Agent 环境里三件套拒绝。
10. **stdio 协议的 stdout 只给协议**：`syndica mcp` / `syndica acp` 进程里任何日志、警告、SDK 的 `basicConfig` 都不得写
    stdout；日志经脱敏 handler 写进工作区之外的日志文件，根 logger 在 import SDK 之前装好 handler（让 SDK 的
    `basicConfig` 成为空操作）。
11. **协议适配只做映射，不复制 Runtime 逻辑**：会话、轮次、预算、确认、提问、中止、恢复都经已有的装配与 `Live`；
    适配层不自己跑工具循环、不自己判危险、不自己存会话。
12. **会话与 trace 不被绕过**：每个协议请求落在一个 Syndica 会话里（Web UI 能看到、`syndica trace` 能读）；OpenAI 与
    A2A 的无状态请求也建会话，不是一次性的裸模型调用。
13. 面向调用方的错误三件套；注释只写约束；用例名即断言；公开面加名字不破坏、去名字破坏——能私有就先私有。

## 公开契约（发布即承诺）

### 内核新增

- **`kernel.external_calls`**（新模块，名字进 `kernel.__all__`）：

  ```python
  @dataclass(frozen=True)
  class ExternalCallPolicy:
      judge: DangerJudge
      policy: DangerPolicy
      untrusted_high_risk: Disposition = Disposition.BLOCK
      guard: DangerJudge | None = None          # 命中即无条件拒绝（开发模式的 git 写 / 删根）
      confirm: ConfirmationHandler | None = None  # 处置为 CONFIRM 时问谁；None 按拒绝

  async def call_external(
      runtime: Runtime | None, tool: Tool, args: Mapping[str, object], *,
      caller: str, agent_id: str | None, policy: ExternalCallPolicy,
      provenance: TrustLevel = TrustLevel.UNTRUSTED,
  ) -> ToolResult
  ```

  判定 → 守卫 → 处置（`disposition_of`，溯源缺省不可信）→ 在 `UNTRUSTED` 的调用信任下执行（写入记成不可信）→ 结果
  的 `trust` 收紧为不可信 → 记一个 TOOL_CALL span（`caller` 记进属性：`mcp-client` / `acp-agent:<名>` …）。被拒绝时
  交回一个说明了规则 ID、等级、原因与下一步的 `ToolResult`（不抛），工具自己抛的 `SyndicaError` 照样上抛。
  `agent_id` 给定时按那个 Agent 的工作区路由（托管的 ACP Agent 在它宿主 Agent 的工作区——可能是隔离副本——里读写）。
- **事件新种类 `external_activity`**（payload：`source`（`acp` / `a2a` / `mcp`）、`name`、`activity_id`、`kind`、
  `status`、`title`）：外部 Agent 自己报告的工具调用与计划进时间线；只是展示，不进轨迹、不参与配对。
  `KERNEL_EVENTS` 整张断言随之更新，SSE schema 随之生成。
- 其余内核面不扩：外部 Agent 是 LLM 适配器（`LLM` 协议不变）、外部工具是 `Tool` 子类（`Tool` 协议不变）。

### 配置

- `.syndica.yaml` 新根键 `interop`（只能按名字引用凭证，见硬约束 4）：

  ```yaml
  interop:
    mcp:
      servers:                      # Syndica 的 Agent 用的外部 MCP server
        - name: files               # [a-z][a-z0-9_-]{0,31}，全表唯一
          command: [npx, -y, '@modelcontextprotocol/server-filesystem', .]   # stdio：Agent 环境、工作区根
          pass_env: [FOO]           # 同 workspace.pass_env 的校验
          roles: [Worker]           # 哪些角色拿到它的工具；缺省谁都不拿
          high_risk: [write_file]   # 按 HIGH 判（缺省规则见阶段一）
          low_risk: [read_file]     # 按 LOW 判
        - name: tracker
          url: https://mcp.example.com/mcp    # Streamable HTTP；鉴权只来自用户级配置
      serve:
        tools: [Read, Grep, Glob]   # 经 MCP 暴露给外部客户端的 Syndica 工具；缺省就是这三个
    acp:
      agents:                       # 托管的第三方 ACP Agent
        - name: gemini
          command: [npx, -y, '@google/gemini-cli', --experimental-acp]
          pass_env: []
    a2a:
      agents:                       # 远端 A2A Agent
        - name: researcher
          url: http://127.0.0.1:9999/
  agents:
    - name: Gemini
      description: 用 Gemini CLI 做事
      model: acp:gemini             # 外部 Agent 作为角色（用户 2026-10-09 选定）
      tools: []
  ```

  `command` 只收字符串列表（不经 shell）；`describe()` 把每个 `command` / `url` 逐字列给人看。`acp:<名>` / `a2a:<名>`
  指向未声明的名字是三件套错误。
- 用户级配置 `interop.yaml`（`store_path` 的同一目录，必须在工作区之外，权限 0600）：

  ```yaml
  credentials:
    acp:gemini:                                  # 额外透传给这个外部进程的宿主变量
      command: [npx, -y, '@google/gemini-cli', --acp]
      env: [GEMINI_API_KEY]
    mcp:tracker:                                 # 发给远端的 Authorization: Bearer <值>
      url: https://mcp.example.com/mcp
      bearer_env: TRACKER_TOKEN
    a2a:researcher:
      url: https://researcher.example/a2a/
      bearer_env: RESEARCHER_TOKEN
  ```

  只存变量名、不存值；每一项钉住它能去的地方（`a2a:` 钉 `url`，`acp:` 钉 `command`，`mcp:` 二选一，`url` 配
  `bearer_env`、`command` 配 `env`），项目声明的那个对象逐字相同才交出凭证，不同就拒绝启动这个对象（见 P2）。
  `http://` 上的 Bearer 只给回环主机。名字对不上任何已声明的外部对象时 doctor 报一项警告（不报错：用户级配置跨
  工作区共用）。

### server（`syndica.server` 扩展）

- `syndica up --api-token`：额外打印一个机器客户端用的 Bearer 令牌（`Credentials.issue_api_token()`，内存里、进程
  生命周期、只发一次）；与浏览器令牌同一套校验。
- 新路由（都在静态兜底之前，都经 `_Guard`；OpenAPI 快照收进它们，标 `x-syndica-protocol`，请求与响应体按对方协议
  只写引用不展开）：

  | 路由 | 协议 | 认证 | 缺 extra |
  |---|---|---|---|
  | `GET /.well-known/agent-card.json` | A2A | 公开 | 501 三件套 |
  | `POST /a2a/` | A2A JSON-RPC（v1.0 + 0.3 兼容，流式 SSE） | Bearer | 501 |
  | `GET, POST, DELETE /mcp` | MCP Streamable HTTP（两个时代） | Bearer | 501 |
  | `GET /v1/models` | OpenAI | Bearer | — |
  | `POST /v1/chat/completions` | OpenAI（含 `stream`、`tools`） | Bearer | — |
  | `POST /v1/responses` | OpenAI Responses（含 `stream`、function tools、`previous_response_id`） | Bearer | — |

  路由表与是否装了 extra 无关（快照确定）；缺 extra 的路由交回 501 与安装指引。
- 会话续接：OpenAI 请求可带 `X-Syndica-Session: <sid>`，响应总带它；Responses 的 `id` 是 `resp_<sid>_<序号>`，
  `previous_response_id` 续接那个会话。A2A 的 `contextId` 就是会话 id。
- CLI：`syndica mcp [--config PATH]`（stdio MCP server）、`syndica acp [--config PATH]`（stdio ACP agent）、
  `syndica up --api-token`、`syndica doctor` 报告外部对象（能否起、协商到的版本、工具清单与被排除的工具）。

## 阶段与任务

> 每个任务：实现 + 测试同出；一次全套；阶段末一轮后台对抗评审（不挡提交，报告边写边落盘）；阶段末导出验证。
> 每个协议适配有**固定 fixture 与黄金文件**：一条脚本化场景的线上往返（JSON 行，id / 时间戳归一化）与黄金文件逐字比对，
> 改映射就得看 diff（路线图静态验收）。对端一律用官方 SDK 当一致性实现。

### 阶段零：共用基础

- `check_deps`：kernel 禁止的外部包加五个协议 SDK；三个新 backend 进组件识别；用例。
- `kernel.external_calls`（上面的签名）：用例覆盖判定命中 / 守卫命中 / 处置三种 / 溯源可信与不可信 / 写入记成不可信
  （外部写入的文件之后读回不可信）/ 结果信任收紧 / trace span / 工具自己抛错——每种处置在 `max_tool_concurrency`
  无关（它一次一个调用），但与 `ToolExecutor` 对同一组（工具、实参、溯源）给出**同一个结论**（逐格对照用例）。
- 事件 `external_activity`；`KERNEL_EVENTS` 整张断言、SSE schema、前端类型重新生成。
- 配置：`interop` 根键的解析与校验（名字、`command` 只收列表、`pass_env` 同规则、`roles` 指向存在的角色、`acp:` /
  `a2a:` 模型名指向已声明的对象、项目配置里任何形似密钥的东西拒收、未知子键拒收）；`describe()` 加 interop 一节；
  用户级 `interop.yaml` 的读取（工作区之外、0600、只存变量名）。拒绝面按类型族枚举。
- server：`create_app(..., adapters=())`（一个适配交出路由与一个可选的 lifespan 上下文；挂在兜底之前）；
  `Credentials.issue_api_token()` 与 `up --api-token`；Agent 环境里拒绝；OpenAPI 的 `x-syndica-protocol` 路径与 501
  的缺 extra 路径；`api-changes.md`。
- 外部进程监管（backend 内各自一份，backend 之间不共享代码）：起在新会话组、stderr 经脱敏逐行进日志（有上限）、
  终止阶梯（关 stdin → 宽限 → SIGTERM 组 → 宽限 → SIGKILL 组），用例在会话关闭 / 关机 / Ctrl-C / 子进程自己先死四条
  路径上查进程表（含孙进程）。

### 阶段一：MCP client（`backends/mcp`）

- 连接：stdio（`StdioServerParameters(command, args, env=<完整的 Agent 环境 + pass_env + 用户级透传>, cwd=工作区根)`——
  SDK 只继承六个变量，Agent 环境必须显式交给它）与 Streamable HTTP（鉴权头来自用户级配置；我们自己的 `httpx2` 客户端
  带超时）；`Client(mode='auto')`，协商到的版本记进 trace 与 doctor；关掉客户端响应缓存（结果要每次真取）。
- 工具包装：分页取全；名字 `<server>__<tool>`（规整到 `[A-Za-z0-9_-]{1,64}`，撞名三件套）；`inputSchema` 内联
  `$ref`（有环或超深就排除这个工具，ERROR 日志 + doctor 列出，不静默）；描述截到 1024 字符、去控制字符；每个工具
  生成一个子类，`__tool_command_args__` = 全部顶层属性（shell 规则看得见每个实参）、`__tool_external_input__ = True`；
  执行前按 `inputSchema` 校验实参（`jsonschema`，三件套）；结果：文本拼接、`structuredContent` 进 `meta` 与一段 JSON
  文本、图片换成占位说明；`isError` 的结果照交给模型并在 `meta` 标出；一律 `UNTRUSTED`。并发：一律串行（注解是
  对方的自述）。
- 风险：backend 带一条危险规则 `mcp.external_tool`：配置 `high_risk` → HIGH；`low_risk` → LOW；否则注解
  `readOnlyHint: true` 且 `destructiveHint` 不为真 → LOW，其余 HIGH。开发模式的处置表给它 CONFIRM（有人就问、没渠道
  就拒）。诚实后果写进文档：轨迹一旦读过不可信内容，HIGH 的外部工具按 `untrusted_high_risk` 拒绝——与 `Bash` 同一套。
- 装配：会话装配时（异步，Runtime 建好之前）连上 `roles` 用到的 server、取工具，交给一个 Runtime Module `mcp`
  按角色装；server 中途退出时调用交回三件套（不自动重连，v1）；超时取 `min(每个 server 的超时, 墙钟剩余)`。
- 用例与 fixture：SDK 写的假 MCP server（两个时代各一）、分页、`$ref`、坏 schema、`isError`、超时、取消、server 崩溃、
  环境里看不到宿主密钥（除非用户级透传）、HIGH 工具在不可信轨迹后被拒、黄金文件。E2E：脚本化模型的 Worker 用假
  server 的工具完成一件事，trace 里有这次外部调用。

### 阶段二：MCP server（`server/mcp`）

- 低层 `Server`：`tools/list` 来自 `interop.mcp.serve.tools`（缺省 Read / Grep / Glob，注解 `readOnlyHint`；写与命令类
  显式加，用户 2026-10-09 选定）；`tools/call` 校验实参后经 `call_external`（调用方 `mcp-client:<clientInfo.name>`，
  溯源不可信）；`resources/*`：产物（`syndica://artifact/<id>`，文本内容经脱敏；二进制给元数据不给内容）；
  `prompts/*`：角色（名字、描述、system prompt）。`get_tool_input_schema` 设好；每个处理器接住一切异常（不让旧时代的
  `code: 0` 回显原文）。
- 传输：`syndica mcp`（stdio；日志不碰 stdout；工作区与信任同 `syndica up`；Agent 环境里拒绝）与 `syndica up` 上的
  `/mcp`（Bearer；我们的 `_Guard` 管 Host / Origin，再给 SDK 一份 `TransportSecuritySettings`；lifespan 里进
  `session_manager.run()`）。每个 MCP 连接（stdio 进程或 HTTP 会话）一条 trace。
- 用例与 fixture：SDK 客户端两个时代（stdio + HTTP）列工具、调 Read / Grep、读产物、取提示；Write 未开时不在清单、
  开了之后经判定（`Bash` 的 `rm -rf /` 被拒、`git commit` 被守卫拦）；外部写入的文件读回不可信；令牌错 401；Host 坏
  421；异常不回显；版本不认识 -32022；黄金文件。

### 阶段三：ACP agent（`server/acp`，`syndica acp`）

- `initialize`：协议版本只认 1（对端给更大的答 1，给 0 或我们答 1 之后对端不认就三件套）；能力：`loadSession`、
  提示只收文本（其余内容块三件套拒绝）、MCP 只收 stdio（`mcpCapabilities.http/sse = false`）。
- `session/new(cwd, mcpServers)`：`cwd` 必须是一个配置已被信任的工作区（不在 stdio 上问人；没信任就三件套指向
  `syndica config trust`）；客户端给的 stdio MCP server 经组合根注入的 MCP client 接进这个会话（它们是人的编辑器
  配置的，按阶段一的规则跑在 Agent 环境里、结果不可信）。会话模式 = 角色（`modes` 列出角色，只在第一条提示之前可换，
  之后换三件套拒绝）。
- `session/prompt`：文本投递给根 Agent；会话事件 → `session/update`：assistant 块 → `agent_message_chunk`；
  `tool_call_started` / `finished` → `tool_call` / `tool_call_update`（工具名映射 ACP 的 `kind`，输出经脱敏截断）；
  `TodoWrite` → `plan`；确认请求 → `session/request_permission`（`allow_once` / `reject_once`；答复经 `Live` 的待答表，
  以人的身份）；AskUser / AskUserQuestion → 一条 agent 消息（选项逐字列出）并以 `end_turn` 结束这次提示，下一条提示
  就是答复（不合选项就三件套、继续等）。停止原因映射：COMPLETED → `end_turn`、MAX_TURNS → `max_turn_requests`、
  BUDGET → `max_tokens`（附一条说明用掉了哪一维）、ABORTED → `cancelled`；ERROR 是 JSON-RPC 错误（三件套）。
- `session/cancel` → `abort`，那次提示以 `cancelled` 返回；`session/load` → 恢复会话并把历史按 `user_message_chunk` /
  `agent_message_chunk` 重放；stdin EOF → 挂着的确认按拒绝、会话 checkpoint、退出。
- 用例与 fixture：SDK 客户端驱动 `syndica acp`（真子进程，脚本化模型）：建会话、提示、收到 tool_call 与消息、一次确认
  批准与一次拒绝、提问与答复、取消、恢复、非文本内容被拒、版本不对、日志不进 stdout、异常不回显；黄金文件。

### 阶段四：ACP client（`backends/acp`，托管第三方 ACP Agent）

- 适配器 `AcpAgentModel`（`LLM`）：每个用它的 Syndica Agent 一个外部进程与一个 ACP 会话（第一次调用时起，Agent 拆除 /
  关机时收）；`initialize` 时声明 `fs.readTextFile` / `fs.writeTextFile` / `terminal`，协商不到 1 就三件套；
  `session/new(cwd=那个 Agent 的工作区根——可能是隔离副本)`。
- `create(messages)`：把上次回答之后的新用户内容（第一次加上 system prompt 与任务）作为提示发出；收 `agent_message_chunk`
  拼成回答；`tool_call` / `tool_call_update` / `plan` → `external_activity` 事件；回答以 `UNTRUSTED` 的 assistant 块交回。
  截止时刻（`model_call_limit`）与取消：发 `session/cancel`、有界等它返回，等不到就杀整组；用量交给内核按估算记。
- 客户端回调（都经 `call_external`，`agent_id` = 宿主 Agent，调用方 `acp-agent:<名>`）：`fs/read_text_file` → Read；
  `fs/write_text_file` → Write（记成不可信）；`terminal/create`（`command` + `args` 按 shlex 拼、`env` 里形似密钥的名字
  拒收、`outputByteLimit` 照办）→ Bash 后台；`terminal/output` / `wait_for_exit`（轮询，受墙钟约束）/ `kill` / `release`。
  `session/request_permission`：`read` / `search` / `think` 直接 `allow_once`；其余 `kind` 走 Syndica 的确认（Web UI 或
  CLI 有人就问，没渠道就 `reject_once`）——之后真做的读写与命令仍各自过判定。
- 进程：Agent 环境 + 用户级配置点名的透传变量；stderr 有人读（硬约束 5）；缺回调不会发生（我们全实现）。
- 用例与 fixture：SDK 写的假 ACP Agent（读、写、开终端、要权限、刷 stderr、不理会取消、崩溃）托管成角色，经脚本化的
  Orchestrator `Delegate` 派活；外部写入读回不可信；高风险命令被拒；超时与取消不留进程；黄金文件。

### 阶段五：A2A（`server/a2a` 与 `backends/a2a`）

- server：agent card（名字 = 工作区目录名、技能 = 角色、接口 = `http://127.0.0.1:<port>/a2a/` JSONRPC 1.0 与 0.3、
  Bearer 安全方案、`streaming: true`）；执行器：`contextId` ↔ 会话（没有就新建，角色取消息 `metadata["syndica.role"]`、
  缺省 Orchestrator），一次消息 = 一个任务 = 一轮；会话事件 → 状态更新（WORKING 带 agent 文本）、提问 → INPUT_REQUIRED
  （对端带同一个 `taskId` 回消息即答复）、确认 → 按 `Live`（UI 有人就等人，没人就拒绝）、完成 → 产物（最终回答）+
  COMPLETED、错误 → FAILED（三件套，不回显异常）、`CancelTask` → `abort`。鉴权由我们的中间件做（SDK 不做）。
- client：适配器 `A2AAgentModel`（`LLM`）：解析 card（我们自己的 `httpx` 客户端与超时、`A2A-Version` 头）、每个 Syndica
  Agent 一个 `contextId`；`create` 发新用户内容、收流、拼最终文本与产物；INPUT_REQUIRED → 把对方的问题作为回答交回，
  记住任务，下一次调用的内容作为答复发进同一个任务；`UNTRUSTED`；截止与取消发 `CancelTask`；对端 `A2AError` /
  `A2AClientError` 都换成三件套。
- 用例与 fixture：SDK 客户端对 Syndica（v1.0 与 0.3 各一条）：发消息、流、取任务、取消、缺版本头、令牌错、执行器异常不
  回显；Syndica 的角色对 SDK 写的假 A2A Agent 派活（含 INPUT_REQUIRED 一来一回）；双向各一条黄金文件。

### 阶段六：OpenAI 兼容 HTTP（`server/openai_http`）

- `GET /v1/models`：角色。`POST /v1/chat/completions` 与 `POST /v1/responses`：
  - **会话**：没带 `X-Syndica-Session` / `previous_response_id` 就新建（角色 = `model`）；首条投递是把请求里的消息
    按角色渲染成一段文字（`system` / `developer` 作为调用方给的说明，历史轮次逐条引用），以人的身份、可信投递——调用方
    持有 API 令牌，是人自己的程序；`tool` 消息（客户端工具的结果）不可信。带了就续接：只投递最后一条 assistant 之后的
    新内容。
  - **客户端工具**：请求里的 `tools` 在新会话里装成代理工具（名字与客户端的一致；和 Syndica 工具撞名 400 三件套；
    会话建好之后换工具集 400），模型调用代理工具时这次响应以 `finish_reason: tool_calls`（Responses：`function_call`
    输出项）交回；代理工具等客户端下一次请求里同一个 `tool_call_id` 的结果（`wait_for` 的 `Reply`，有上限，到点给模型
    一段「客户端没交回结果」）。Syndica 自己的工具在服务端跑、不出现在响应里。
  - **流式**：按块合成（LLM 层没有流式）：assistant 块整块一个 delta，客户端工具调用一个 `tool_calls` delta，最后
    `finish_reason` 与（要了 `include_usage` 时）usage 块、`data: [DONE]`；Responses 按 `response.*` 事件序列。客户端
    断开不中止这一轮（结果留在会话里，UI 看得见），文档写明。
  - **参数**：采样参数（`temperature` / `top_p` / `max_tokens` 等）收下并忽略、在响应头 `X-Syndica-Ignored` 里列出；
    改变语义的（`n > 1`、`logprobs`、`audio`、非 function 的内置工具、`response_format: json_schema`）400 三件套；
    确认请求按 `Live`（UI 有人就等人）。错误体是 OpenAI 的形状且带三件套；不发 `x-should-retry: true`（POST 不该被重放）。
- 用例与 fixture：`openai` SDK（`max_retries=0`，显式 `base_url` 与 `default_headers`，环境里的 `OPENAI_*` 清掉）对
  `syndica up`：非流 / 流 / 客户端工具往返 / 续接 / Responses 的同一组；400 / 401 / 404 的异常类；Agent 的确认在 UI
  被批准；黄金文件。

### 阶段七：收口

- 真实客户端（用户 2026-10-09 同意在临时目录里装第三方 CLI、key 只在子壳里 source）：MCP Inspector 的 CLI 模式对
  `syndica mcp` 与 `/mcp`；Gemini CLI 作为托管的 ACP Agent 在免费 Gemini key 下完成一件读写工作（key 只经用户级
  `interop.yaml` 透传）；`openai` SDK 对 `syndica up`（背后是免费 Gemini）；`a2a-sdk` 客户端对 Syndica、Syndica 对一个
  `a2a-sdk` 写的远端 Agent。全程查 key 零泄露、外部进程不留。
- spec §9.3 / §15、路线图、README（每个协议的接入方式、信任与密钥的边界、`interop.yaml`）；收口审计
  `docs/audits/<date>-m10-final-audit.md`；收口对抗评审一轮。

### 明确不做（附理由，收尾时复核）

- MCP 上的「派一个 Syndica Agent 干活」工具：Agent 级的互通由 ACP 与 A2A 承担；MCP 侧只暴露工具、产物与提示。
- MCP server 的反向请求（采样、征询、roots）、订阅与可续传事件存储：新时代下没有反向通道，旧时代下我们不需要。
- 外部工具 / 外部 Agent 的「声明为可信」：要信任就别经协议接（硬约束 2）。
- MCP 的 OAuth 授权服务器、A2A 的推送通知与 REST / gRPC 绑定、ACP 的 HTTP / WebSocket 传输与不稳定方法
  （fork / resume / close、elicitation）：v1 各取最常用的那一种传输。
- LLM 层的流式：OpenAI 的流按块合成足够兼容；真流式要改 LLM 协议，归 v1 之后。
- 外部 server / Agent 崩溃后的自动重连：给三件套、由人重开会话。

## 决策日志

- **P0（计划，2026-10-09）** 本文件初稿。用户选定：官方 SDK 进各自的 extra、OpenAI HTTP 不引 SDK 挂在 `syndica up` 上；
  MCP server 缺省只读、写与命令显式打开且仍过判定；ACP 双向；可以装第三方 CLI 跑真实场景；OpenAI 做 chat completions
  与 Responses；外部 Agent 作为角色；机器客户端令牌由 `up --api-token` 打印、只在内存；密钥只从用户级配置来。
  架构选择：被调用的四个适配都进 `syndica.server`（共用 `Live` 与外发出口；stdio 入口经组合根），调用外部的三个各成
  backend；外部 Agent 是 LLM 适配器、外部工具是 `Tool` 子类；内核只加 `call_external` 与 `external_activity`。
- **P1（实现约束，2026-10-09）** `call_external` 与 `ToolExecutor` 对同一组（工具、实参、溯源）的判定、不可信脚本
  升级与处置结论相同（含 `max_tool_concurrency` 1 与 4）。两处有意更严，不并回去：执行期间的调用信任恒为
  `UNTRUSTED`（外部写入读回不可信，即使用这次溯源是可信的）；工具交回的结果收紧为不可信。拒绝说明是内核写的，
  保持可信，避免把随后放进轨迹的会话整段升级。守卫命中即拒绝，不咨询策略、也不看 `untrusted_high_risk`。
  `confirm` 已装但没有 Runtime 或 `agent_id` 是配置错误，不是静默拒绝。项目配置的 `pass_env` 与 interop 的
  `pass_env` 走同一套拒收；用户级 `interop.yaml` 允许点名密钥变量，但必须是变量名、权限 0600、且在工作区之外。
  对不上这份项目配置的用户级名字由 doctor 警告，不报错。
- **P2（收口评审处置，2026-10-09）** 第二方评审对 `b1ec080` 给出 2 Blocking / 5 High / 若干 Medium，68 条变异 35 条
  存活。分五条互不重叠的线修，另有几处跟进：
  - 三个会话适配（A2A、OpenAI、ACP）只认根 Agent 的回答、结束与失败；子 Agent 的提问与确认照样交给人，答复交回
    提问的那个 Agent。OpenAI 只把根上、点名客户端代理的工具调用交给客户端。根出错时三个适配都只报异常类型。
  - 托管的 ACP Agent 只拿到所属角色冻结后的工具表与 `danger.roles` 处置：`fs/read_text_file` 要 `Read`，
    `fs/write_text_file` 要 `Write`，`terminal/*` 要 `Bash`；`--no-write` 下写与终端回调拒绝。理由：`call_external`
    不经 `PRE_TOOL_USE`，不这样收窄，只读 run 与角色白名单对外部 Agent 都不生效。
  - 用户级凭证钉住目的地（上文）。参照 OTLP 的先例：项目配置是不可信的，它选的地址不能收到用户的凭证。对不上时
    拒绝启动而不是不带凭证去连：静默不发会把一次攻击变成说不清原因的鉴权失败。
  - stderr 整行先脱敏再截断（单行上限 64 KiB，超长的退到最近的空白）；MCP stdio 服务与托管 ACP Agent 关闭、被取消、
    崩溃之后不留后代，`setsid` 出去的也收。
  - A2A 真会话路径与取消路径兜底，异常只留类型名；A2A 客户端没有预算时按配置超时；ACP 紧挨着的两条提示、取消后的
    下一条提示不再丢失或拿到上一轮的尾巴。
  - `call_external` 的守卫不认 syndica 之外的工具自己声明的 `__tool_command_args__ = ()`，与开发期守卫同一条约定。
- **P3（逐条复核之后的取舍，2026-10-10）** 独立子代理把本计划逐条对到代码与用例，查出几条与计划不符、又没登记的
  地方。能改的都改了（见收口审计「逐条复核」一节），下面几条是有意不照计划做：
  - 阶段三的「`TodoWrite` → `plan`」：Syndica 没有 `TodoWrite` 工具，这条映射没有来源，不发 `plan` 更新。将来有了
    计划类工具再接。
  - 硬约束 11 写「答复经 `Live` 的待答表」：`syndica acp` 是独立的 stdio 进程，不起 HTTP server，没有 `Live`。
    ACP 的确认答复走 Runtime 同一条人的答复路径（`sender='human'`），与 `Live` 最终调用的是同一个入口。
  - 硬约束 12「每个协议请求落在会话里」对 MCP server 不适用：MCP 只暴露工具、产物与提示，不派 Agent（「明确不做」
    第一条），阶段二要求的是每个连接一条 trace。
  - 硬约束 6「协议响应只经 server 的外发序列化函数交出」：MCP Streamable HTTP、A2A JSON-RPC 与 ACP NDJSON 的正常
    响应由各自的 SDK 序列化，适配层能控制的是交给 SDK 的每个字段——处理器在交出之前逐字段脱敏、接住每个异常；
    版本错误、鉴权失败这些在 SDK 之前就回的响应走 `json_response` / `redacted`。
  - `syndica.backends.mcp` 的 `ExternalProcess` / `ProcessSupervisor` 没有活路径，但它们是已导出的名字，保留，并与
    MCP stdio 客户端用同一个进程树收尾。
  - 阶段五写 A2A 客户端「收流」：客户端用非流式 `SendMessage`。它是 LLM 适配器，`create` 交回整段回答，而 LLM 层的
    真流式本来就在「明确不做」里，收流带不来回答上的区别；代价是一个任务的第一条消息被取消时远端收不到 CancelTask
    （那时还没有任务 id），收口审计「还没做」里写明。
  - 硬约束 8 的 MCP 版本门只在 HTTP 上：`syndica mcp` 的 stdio 由 SDK 按 MCP 规范协商（对端要的版本不认识时答一个
    自己支持的版本，由对端决定断不断开），没有另加一道。
  - 硬约束 11 提到的「答复必须是选项之一」在 ACP、A2A、OpenAI 三个适配里各写一份：它们收到答复的协议消息各不相同，
    规则相同，用例各自钉住。

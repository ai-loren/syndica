**由内核执行并校验**五条不变量（工具调用配对、SP 不参与、任务消息与当前周期存活、环境事实存活、信任不可降），

注入历史不进 SP、缓存同一份块。

**Architecture:** 新增两个 Store Protocol（`SessionStore` 见 spec §4.4 已设计并由本里程碑补齐缺口、`MemoryStore`
本里程碑新设），各带零依赖的内存 + 文件实现与随发行版发布的契约套件，**文件实现在 `kernel/stores/`**（与
`FileTraceStore` 同层，守卫 IO 的 `O_NOFOLLOW` / `dir_fd` / 硬链接 / FIFO 帮手抽到一个私有共享内核模块，两个文件
store 与 `file_trace` 共用）。三件跨切面的东西先于一切阶段做（**T0**）：内核署名的历史块原语（带
`extra['syndica.kind']` 标记与幂等键，env_fact / memory / compaction / resume_note 都是它）；内核在 turn 边界跑的
压缩步骤与轨迹改写 API（不经 `append`、在任何窗口之外）；Runtime 持有宿主的 `Redactor` 与一个把记录脱敏成只能
进 store 的类型的收口函数。会话持久化不动 turn 循环语义：内核在工作周期收尾（`Runtime._finish`，进 ZOMBIE 之前）
与每 N 轮存盘；恢复经 `ensure_active`（spec §4.2 唯一激活入口）从记录重建上下文、factory 按 `SessionMeta.agent`
经 catalog 解析、turn 计数在内核里种回。压缩是 `CompactionStrategy` 协议（`async`）+ 驱动它的 Runtime Module：
Module 只给策略与触发判断，内核执行、校验、归档、改写、重建基线、记 trace。分层记忆是 `MemoryStore` + 一个记忆
Module：短期按 store 发的 `seq` 记、累积到阈值整理为分段的长期 `MemoryDigest`（整理读到 `through_seq` 为止、原子
换摘要并裁掉已整理的条目），按角色与工作区分层注入历史。目标导向型压缩依赖 M7 的 Rubric，**本里程碑不做**，留

**Tech Stack:** 不新增运行依赖。会话与记忆的文件实现用标准库 `json` + 原子写（临时文件再 `os.replace`），
守卫同 `FileTraceStore`。摘要型压缩与长期记忆整理用现有 LLM 抽象的一次性调用（关缓存写入、记进 replay 的

## 硬约束（沿用，违反即打回）

与 M1–M5 相同，`AGENTS.md` 为准。本里程碑尤其承重的：

1. **kernel 不依赖 surface / backend，不读环境变量，零重依赖。** 会话 / 记忆的文件实现与 `FileTraceStore` 同层
   （`kernel/stores/`，同步 IO、`root` / 全局记忆目录由宿主传入，内核不知道工作区在哪），守卫 IO 帮手抽成私有
   共享内核模块。kernel 只认 Protocol。CLI 只挑根路径、核对 `.syndica` 上级（与 traces 一致）。
2. **公开 API 全量类型标注。** 新增的 Protocol、dataclass、Flag key、Module 清单字段、落盘格式版本全部计入公开面。
3. **落盘与外发一律先过 `Redactor`，在写入之前、截断之前，且收口在内核一处**（P7）：Runtime 持宿主的 `Redactor`，
   内核把记录 / 记忆 / 快照脱敏成只有脱敏模块能构造的类型再交给 store；脱敏**逐叶**只动内容文本、工具参数、工具
   输出，**绝不**改 role / `ToolCall.id` / `tool_call_id` / `extra['message_id']` / provider 私有键（`thought_signature`
   等）；脱敏后在交给 store 前重校验配对与 id 唯一。压缩的截断走内核帮手「先脱敏再截断」。每条新落盘点进 AST 守卫。
4. **前缀缓存纪律（spec §5.2）是头号陷阱。** 恢复、压缩、记忆注入都改历史：
   - 恢复沿用缓存语义；环境事实幂等注入（按 `syndica.kind=env_fact` 的幂等键查，恢复 / 分叉不重复注入）。
   - 压缩在内核 turn 边界一步做完，之后 `drift.rebaseline(agent_id, reason='compaction')` 一次性重建基线，不每轮漂移；
     尽量让头部（任务、环境事实、记忆块）字节不变以保住缓存前缀。阈值与目标分开（迟滞：到 80% 触发、压到 50%），
     压不下去就退避并记一次日志，避免每轮抖动。
   - 记忆**缓存同一份块**，仅压缩步骤与真正的新会话时重载（不按墙钟过期）；恢复**复用存下的记忆块**、不重新拉取。
   - 摘要型压缩、长期记忆整理、生成标题都是**一次性调用、关缓存写入**（请求带 `cache_write=False`，backend 认或忽略）。
5. **压缩不得降低信任：`provenance_of(after) ⪰ provenance_of(before)`（P4，spec §8.8 不变量 5、§12.2 #2、§17 #84）。**
   由**内核**强制，不信任策略：`kept` 里任何与输入块非字节相同的块，内核把 `trust` 置为「策略看到的全部输入里最严
   的」；被丢弃的块里只要有一个 UNTRUSTED，内核在 `kept` 里留一个署名的 compaction 标记块带 UNTRUSTED；反序列化
   会话时 `trust` 缺失或未知按 UNTRUSTED（或拒收）。
6. **记忆信任由内核定、不可信永不进全局（P10 / P12）。** 条目信任由内核在记录时按 `call_trust()` / `provenance_of`
   取，不由调用方给；`MemoryDigest` 按分段带信任；不可信条目**永不晋升全局**，工作区级放进单独的 UNTRUSTED 分段、
   按需（`RecallUntrusted` 一类）以独立的被包裹的 UNTRUSTED 块注入，缺省不注入——否则每个新会话从第 1 轮就不可信、
   高风险操作永远被拒而宿主关不掉。只有会话根 Agent（绑在 `SessionRecord` 上的那个）能写全局，内核在唯一的记忆写
   入路径上强制、拒绝时三件套点名调用方与允许的 scope。`.syndica/sessions`、`.syndica/memory` 进文件工具私有目录。
7. **并发写用乐观并发控制、CAS 基数取 3（spec §4.4 / §8.9 / §13.3；AGENTS.md）。** 契约套件里「读与写之间让出的
   实现必须判不合规」。会话并发见决策（下）；记忆 `consolidate(expected, through_seq)` 是原子换 + 裁剪，`record` 是
   原子追加。
8. **面向调用方的错误三件套**：期望 / 实际 / 下一步。

## 公开契约（发布即承诺）

### T0 的内核原语（先于一切阶段）

- **署名历史块**：内核往历史注入的块带 `extra['syndica.kind'] ∈ {env_fact, memory, compaction, resume_note}` 与一个
  幂等键 `extra['syndica.key']`。这是记忆、环境事实、压缩标记、恢复提示进历史的**唯一**合法途径（Module / 工具不能
  `append`，会在窗口里报错，#112）。环境事实改成单独的 `env_fact` 块（不再拼进 query 文本）——只改新 run 的请求字节，
  要验证 `Fork` 仍共享前缀。
- **压缩步骤与改写 API**：内核在 turn 边界跑（§5.1 第 4 步之后、第 5/6 步之前，在任何窗口之外）。它向 Module 要
  （策略, 是否触发）→ 内核执行策略 → 校验五条不变量 → 归档快照 → 改写轨迹 → `drift.rebaseline` → 记 `compaction`
  trace 事件。`Compact` 工具只置一个「下一轮压缩」请求位，不在工具段里改轨迹。`CONTEXT_OVERFLOW` 钩子调同一步，
  只有真的压下去了才 `skip=True`（否则退避、不空耗 turn）。
- **Runtime 持宿主 `Redactor`** 与 `redacted_record(record, redactor) -> RedactedSessionRecord`（只有脱敏模块能构造
  后者，store 只收它）。

### SessionStore（spec §4.4 + 本里程碑补齐）

```python
class SessionStore(Protocol):
    async def exists(self, sid: str) -> bool: ...
    async def load_meta(self, sid: str) -> SessionMeta | None: ...
    async def load(self, sid: str) -> SessionRecord | None: ...
    async def save(self, sid: str, record: RedactedSessionRecord) -> None: ...
    async def archive(self, sid: str, record: RedactedSessionRecord) -> int: ...
    async def list_metas(
        self, *, status: SessionStatus | None = None, agent: str | None = None,
        workspace: str | None = None,
    ) -> list[SessionMeta]: ...
    async def replace_content(self, sid: str, content: RedactedContent) -> None: ...
    async def delete(self, sid: str) -> None: ...
    async def read_archived(self, sid: str, seq: int) -> SessionRecord | None: ...
```

- `list_metas` 是**闭集**过滤（P6）：只认 `status` / `agent` / `workspace`，顺序按 `updated_at` 倒序；未知关键字由调用
  方不传（Protocol 签名已限定）。`delete` 缺条目是 no-op（与 `unregister` 同）。`read_archived` 让 §8.8「出问题能回看」
  成立；归档只增不补、`archive` 同时把 live 记录的 `SessionMeta.archived` 前移。`save` 缺 sid 是创建；`replace_content`
  只换正文、前移 `updated_at`，缺 sid 抛异常。`created_at` 由调用方（内核）盖、不由 store 盖。
- `SessionMeta`：`sid` / `title` / `agent` / `workspace` / `status`（`SessionStatus` ∈ `{active, archived}`）/ `turns` /
  `archived` / `last_trace` / `created_at` / `updated_at`。字段顺序是契约。
- `SessionRecord`：`meta` + `content: list[ContextBlock]`（根 Agent 轨迹）+ `system_prompt` + `model` + `tools`
  （名字按序，为缓存连续性）+ `flags`。落盘格式带 `schema`（`syndica.session/1`），读到更高版本按 `FileTraceStore`
  的 `NewerTraceSchema` 同样拒收；坏记录「尽量修复、跳过坏子项、明确记录」。`ContextBlock` 序列化round-trip 全字段
  （含 `extra` 的嵌套值、`artifacts`、`ToolCall` 字段序、`trust` 枚举值）。
- **并发（决策，见下）**：`save` 是 last-writer-wins，**文档明说不支持并发恢复同一会话**；宿主在 resume 时用一个
  `O_EXCL` + pid + 陈旧判定的锁文件挡住第二个恢复，第二次 resume 给三件套错误。这关闭路线图 B-01（配 P5）。
- 契约套件 `SessionStoreContract` 随发行版发布；`InMemorySessionStore` 与 `FileSessionStore`（`kernel/stores/`）都过，
  含：并发 `archive` 基数 3（序号互异且 max+1）、「读写之间让出的实现判不合规」、更高 schema 拒收、`ContextBlock`
  全字段 round-trip、坏记录策略。调用方侧 spy-store 用例（P24）：`sessions list` 不调 `load`、`show` 调一次 `load`、
  missing-queue 路径只调 `exists`、单会话查询不走 `list_metas`。

### Resume contract（P2）

- `Runtime(..., sessions: SessionStore | None = None)`。身份规则：`sid` = 根 Agent id，`AgentInfo.session_id = sid`。
- `ensure_active(id)`：Agent 不在注册表且 `sessions.exists(id)` 时 → `load()` 一次 → 按 `SessionMeta.agent` 从 catalog
  解析 factory（缺了给三件套错误）→ 在内核里种回 Context 与 turn 计数 → 带 `session_id` 注册 → 起驱动任务。
  `find` 与 `send(activate=False)` **绝不**碰 store；`_on_missing_queue` 只调 `exists`。
- turn 计数种回，`max_turns` 跨恢复仍绑（§5.1：turn 永不重置）。安全相关 flags（`untrusted_high_risk`、danger policy）
  恢复时取「当前或更严」，不用快照里的旧值（P22）；SP / model / tools 快照只为缓存连续性，不一致时 stderr 给 diff
  并按当前值继续（接受一次性失配）。

### 压缩

```python
class CompactionStrategy(Protocol):
    async def compact(self, request: CompactionRequest) -> CompactionResult: ...
```

- `CompactionRequest`：`blocks`（SP 之外的轨迹）/ `budget_tokens` / `protected`（内核算出的、必须原样存活的块的
  位置集合：任务消息 + 当前周期 + `env_fact` 块；Goal / Rubric 到 M7 additively 扩）/ `summarize`（`async (blocks, *,
  budget_tokens) -> str` 的一次性调用句柄，摘要型用，关缓存、记 replay）。
- `CompactionResult`：`kept` / `dropped` / `note`。内核校验五条不变量后才接受，违反即 `ContractViolation` 点名哪条；
  并**由内核**对 `kept` 里非字节相同的块置信任（最严）、在丢了 UNTRUSTED 时留署名标记块（硬约束 5）。
- 三种基线：`RuleBasedCompaction`（零 LLM，确定性，可回放）、`SummaryCompaction`（摘要前先规则型预压缩、自带预算、
  一次性调用）、`PruningCompaction`。目标导向型留协议位、本里程碑不实现（spec §15）。
- Flag（§5.5 合法键、整数域）：`compaction_strategy`（`rule`/`summary`/`prune`，缺省 `rule`）、
  `compaction_threshold_percent`（1–99，缺省 80）、`compaction_target_percent`（1–99，缺省 50）、
  `checkpoint_every_turns`（缺省 1）、`memory_consolidate_after`（缺省 50）。阈值路径在 `context_window is None` 时关掉
  （一次 WARNING），超窗兜底仍在。

### MemoryStore（本里程碑新设）

```python
class MemoryStore(Protocol):
    async def recent(self, scope: MemoryScope, *, since_seq: int = 0) -> list[MemoryEntry]: ...
    async def record(self, scope: MemoryScope, entry: MemoryEntry) -> int: ...
    async def consolidated(self, scope: MemoryScope) -> MemoryDigest | None: ...
    async def consolidate(
        self, scope: MemoryScope, digest: MemoryDigest, *, expected: str | None, through_seq: int
    ) -> str: ...
```

- `MemoryScope`：`level`（`global` / `workspace`）+ `workspace`（工作区稳定身份，不是 worktree / 隔离副本路径）。
- `MemoryEntry`：`seq`（store 发、单调）/ `kind` / `text` / `trust`（内核记录时定）/ `created_at`。`record` 原子追加、
  返回 `seq`。`MemoryDigest`：`version`（OCC 前提）+ 分段（每段带信任）。`consolidate` 原子换摘要并裁掉 `seq ≤
  through_seq` 的条目；`expected=None` 是 create-if-absent，不符抛 `MemoryConflict`。`recent(since_seq=)` 按 `seq` 排序。
- 契约套件 `MemoryStoreContract`：并发 `record` 无丢失、并发 `consolidate` 基数 3 的 CAS、`expected=None` 语义；
  文件实现跨进程用 `flock` + 版本校验 + `os.replace`（或文档写明单进程 + 锁文件）。

- trace 新增：`compaction` 事件（策略、前后 token 估算、被压块数、`drift rebaseline`、被丢块的 redacted payload ref）、

# 里程碑 12 计划：发布准备

日期：2026-10-10
来源：[路线图](2026-09-23-v1-milestone-roadmap.md)「M12 发布准备」与遗留项归属表里归到 M12 的条目
状态：已完成（发布动作待维护者确认），见 [M12 收口审计](../audits/2026-10-10-m12-final-audit.md)

## 目标

把 Syndica 整理成可公开发布的 v1.0：公开 API 冻结、英文用户文档与文档站、仓库规范、打包与发布配置、CI 矩阵、
demo，并通过路线图列出的四项 E2E 验收。推送、发 PyPI、把仓库设为公开、打 v1.0 标签之前问用户。

## 已定的决定（用户 2026-10-10 选定）

- **D1 CI**：本月没有 GitHub Actions 额度。`ci.yml` 按矩阵写好，本月在本地跑通（macOS 原生、Colima 里的 Linux
  容器、uv 装的 3.11 / 3.12 / 3.13）；额度恢复后用托管 runner 跑一次完整矩阵，作为发布门禁。
- **D2 平台**：v1.0 只支持 Linux 与 macOS；Windows 用户用 WSL2。代码里进程组、`setsid`、伪终端这些 POSIX 接口不加
  Windows 分支；包元数据不声明 Windows。
- **D3 语言**：只英文化用户文档与文档站（README、五分钟上手、概念、API 参考、排错、扩展指南）。运行时的错误
  信息、CLI 输出与代码注释保持中文，文档写明；英文化归 v1.x。AGENTS.md 按它自己的要求译成英文。
- **D4 发行形态**：单个发行包 `syndica` 加 extras（`server` / `openai` / `otel` / `mcp` / `acp` / `a2a` / `trl`），
  不拆成 `syndica-server` / `syndica-runner`。依赖体积靠 extras 控制，分层由 `check_deps` 强制。路线图静态验收里的
  `pip install syndica-server` 换成 `pip install 'syndica[server]'`。

## 硬约束

- 公开面加名字不破坏、去名字破坏：v1.0 之前撤下的每个名字都写进 CHANGELOG 与快照的 diff。
- 快照由人 review：快照变化即公开面变化，测试失败时先看 diff，再决定改快照还是改代码。
- 文档里的命令要么被测试执行或解析，要么明确标为不执行。
- SECURITY 写明：不提供多租户隔离；同进程的第三方代码（Module、backend）无法沙箱化。
- 不发 PyPI、不打标签、不设仓库公开、不推送，除非用户确认。

## 验收

路线图的静态验收与 E2E 验收，按 D1–D4 调整：

- `pip install .`、`pip install '.[openai]'`、`pip install '.[server]'` 等每个 extra 的 smoke 通过。
- 本地矩阵（macOS 与 Linux 容器 × 3.11 / 3.12 / 3.13）全绿；`ci.yml` 写好托管矩阵，下月作发布门禁。
- 文档站构建无断链；README 代码块可执行或明确标记不可执行。
- 包元数据、license、classifiers、`py.typed` 完整。
- 公开 API 快照与 v1.0 冻结清单一致。
- 依赖锁与安全扫描无高危未解释项。
- E2E：干净 Linux 容器里照 README 五分钟内完成一次 CLI run；Web UI 完成多 Agent 任务、人工确认、查看产物；
  MCP / OpenAI SDK 连本地 server 完成一次工具调用；跑一批任务并导出训练数据。

## 明确不做

- Windows 支持（D2）。
- 运行时信息的英文化与本地化（D3）。
- 拆分发行包（D4）。
- 多 Agent 子树持久化（路线图归 v1 之后）；回放文档 v4 与其余标「后续」的遗留项。

## 决策日志

- **P0（计划，2026-10-10）** 本文件初稿，D1–D4 为用户选定。
- **P1（线 A：公开面，2026-10-10）** 公开导入路径是 `syndica`、`syndica.kernel`（kernel 一侧唯一的导入路径）、
  `syndica.kernel.contracts`、`syndica.runner` 与 `llm_openai` / `llm_router` / `otel_otlp` / `trl` 四个 backend；快照在
  `tests/testdata/public_api.json`，参考页 `docs/user/reference/api.md` 由它生成。按内部处理、与计划初稿不同的：
  - kernel 的子包（llm / stores / tools / hooks / protocols / agents）：调用方要的名字 `syndica.kernel` 都重新导出了，
    而子包自己的 `__all__` 里有早先刻意扣留的名字，单独公开就把它们一起公开了。
  - `syndica.cli` / `syndica.server`：契约是命令与 HTTP API（两者都进了快照）；它们的 Python 接缝只有一个实现，冻结
    一个 Protocol 之后加方法就破坏所有实现方。先私有，以后放出来不破坏。
  - acp / a2a / mcp 三个 backend：用户经 `.syndica.yaml` 的 `interop` 用它们，构造签名收着没导出的传输类型。
  - 撤下 `provenance_of`、`strictest_trust`（没有公开签名用到，仍可从 `syndica.kernel.context` 导入）。
  - 长程策略的协议、上下文、动作类型与契约公开；装一个自定义策略仍要经 provisional 的 `LongHorizonModule`，因为
    它的构造签名收着 provisional 的 store，公开安装入口要等那一组一起公开。
- **P2（线 B：打包，2026-10-10）** 版本 `1.0.0rc1` 只写在 `pyproject.toml`，`syndica --version` 读安装的元数据；
  许可证用 PEP 639 写法；sdist 不带测试（测试依赖 docs / scripts / web / examples，只带 tests 是一套跑不通的用例），
  要跑测试的打包者用打标签的仓库归档；`trl` 的安装 smoke 默认不跑（905 MB、首次约 10 分钟），用 `--with-trl` 打开，
  每次发版跑一次。安装 smoke 按 `--prerelease allow` 解析，照用户装 rc 的方式撞依赖的预发布版（线 E 查出的
  httpx 1.0 预发布问题由此在本地先暴露）。
- **P3（线 C：CI，2026-10-10）** `trl`（torch）只装在 macOS 3.13 那一格：Linux 上 PyPI 的 torch 每格多下几 GB 的
  CUDA 轮子，而 TRL 用例测的是本仓对 trl API 的适配，与平台无关；pyright 只跑一格（`pythonVersion` 钉在 3.11）；其余
  extras 每格都装。矩阵查出 6 个真缺陷并修掉（审计列出），以及若干只依赖某个解释器调度与计时的用例。
- **P4（线 D：文档，2026-10-10）** 文档站用 MkDocs Material（`mkdocs<2`：Material 团队说明 2.0 不兼容现有主题）；
  每个代码块要么被测试执行或解析，要么在开围栏的上一行写 `<!-- not-tested: 原因 -->`；README 与 quickstart 里标
  `executed` 的块对着假端点真跑。AGENTS.md 译成英文，三个被中文角色提示词按名字引用的标题保留中文前缀。
- **P5（线 E：验收，2026-10-10）** 验收只从构建出的 wheel 跑，模型是测试夹具里的假端点；只有 README 那一项在干净的
  Linux 容器里，其余三项在全新的 venv 里（Web 那项要浏览器）。它查出 README 的 `pip install --pre` 会装进 httpx 1.0
  的预发布重写版、所有模型调用失败：直接 import httpx 的 backend 所在的 extra 封顶 `<1`。真实模型的验收没有跑（没有
  key）。

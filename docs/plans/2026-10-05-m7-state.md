**Goal:** 让产物在框架里**有身份、有版本、能被验收**，并在没有客观真值时判定「活干完了没有」。具体：写入 / 编辑类
工具触碰过的路径由**内核**自动登记为产物（隐式追踪，不依赖装没装验收 Module），`Deliver(path, kind, note)`（内核
内置工具）把其中的交付物显式提升；产物 `id` 只由规范化路径（加隔离作用域）派生、跨版本稳定，`producer` 逐版本记录；
产物按 `(kind, mime)` 路由到处理器，处理器给预览、语义 diff、格式校验（L1，零 token，产物登记 / 变更即跑）。任务
开工**之前**由一个伴生 Agent 从 **Goal**（唯一权威：intent + 锚点链）投影出 **Rubric**（每条带非空锚点链、可重新打开
追回 Goal，分 `checkable` / `judgment` 两类），`judgment` 条在上下文里可见但验收时**由内核强制**输出 `needs_human`、
不塌缩成 `pass`。Agent 判定完成时（内核 `COMPLETION_PROPOSED` 切点），先按交付物上的 L1 违规零 token 打回，再跑
L2（输出验收，保守偏置）与 L3（结果验收，依据 Rubric 查最终回复与工作区证据）；**裁决状态由内核从 per-rubric 结论
推导**，不信 LLM 自报：有带证据的 `unmet` checkable → `block`，还有未确认的 checkable → `partial`，checkable 全
`satisfied` → `pass`，**没有 active checkable 条或验收器自身失败 → `unverified`**（fail-open 放行但显式标记，绝不
塌缩成 `pass`）。于是轨迹里的裁决是**四值** `pass` / `partial` / `block` / `unverified`。人的反馈（仅限人发的、自带
锚点、常自带产物位置）**自动提议**为一条 `proposed` Rubric，**人确认后 `activate` 才生效**，此后每轮验收带上它；重新
投影保留已确认的反馈条目。Goal / 生效 Rubric / Verdict 经 **M6 的署名历史块**（新增 `HistoryKind.GOAL / RUBRIC /
VERDICT`）注入历史、不进 SP，且**压缩必须保护 Goal 与全部生效 Rubric 块**（§8.8 不变量，不是第四种压缩策略，不延后）。

**Architecture:** 新增一个 Store Protocol（`ArtifactStore`，对齐 spec §4.4）与一个产物处理器注册表（`ArtifactHandler`
按 `(kind, mime)` 建索引、全序更具体优先、同精度重复**启动即 `ConfigError`**），各带零依赖的内存 + 文件实现与随发行版
发布的契约套件，文件实现在 `kernel/stores/`（与 `FileTraceStore` / `FileSessionStore` 同层，复用守卫 IO 帮手）。隐式
追踪、`Deliver`、`ARTIFACT_REGISTERED` 切点都由**内核**做 / 触发（spec §5.4：内核枚举切点由内核在固定位置触发；
§5.6 / #79：`Deliver` 是内核内置工具）——产物身份不依赖验收 Module。Goal 与 Rubric 独立于对话存储（§8.2），存进
一个**私有**的 `RubricStore`（按会话 scope、写入面只收 `RedactedGoal` / `RedactedRubric`，仿 `SessionStore`；先私有、
M12 再定是否公开），经内核私有接缝（仿 M6 `_attach_recall`）在周期开始注入历史，且第一轮 LLM 调用**等到 Rubric 投影
完成**。验收是一套 **Runtime Module**（§5.5）：三个伴生是**不进注册表**的内核 Agent 实例，由 Module 用绑定在主 Agent
**对象**上的闭包构造（不按 `agent_id` 查——那是「作用在错主体」的入口），工具白名单只有 `Read / Grep / Glob`、Portal
用主 Agent 那一份隔离副本、显式装宿主守卫插件、**不挂验收插件**（防递归）、各有独立预算。`Verdict` 的四值语义与
`judgment` 强制在**内核** `Verdict` 构造处（#45 是语义不是策略）；验收策略（提示词、裁决口径、重试）在 Module，
换范式不动内核（但注入接缝是私有的，这一点明说）。Verdict 进轨迹（`HistoryKind.VERDICT`）并随会话持久化、`run`
结果带最终 verdict、CLI 显示四值。

**Tech Stack:** 不新增运行依赖。`ArtifactStore` / `RubricStore` 文件实现用标准库 `json` + 原子写（临时文件再
`os.replace`），守卫同 `FileTraceStore`。L1 校验是纯函数（处理器实现，内核只调 `validate`，传一个绑定 Portal 的

## 硬约束（沿用，违反即打回）

与 M1–M6 相同，`AGENTS.md` 为准。本里程碑尤其承重的：

1. **kernel 不依赖 surface / backend，不读环境变量，零重依赖。** `ArtifactStore` / `RubricStore` 文件实现与
   `FileTraceStore` 同层（`kernel/stores/`，同步 IO、`root` 由宿主传入）。处理器注册表、Rubric / Verdict 类型、验收
   切点、四值语义都在 kernel；三个伴生 Agent 与 L2/L3 的提示词 / 口径 / 重试在 Module。kernel 只认 Protocol。
2. **公开 API 全量类型标注，且面要窄（AGENTS：加公开名不是破坏性变更、去掉是）。** `ArtifactStore` 对齐 spec §4.4
   并公开；`ArtifactHandler` / `Preview` / `Diff` / `Violation` / `ArtifactReader` 公开；`RubricStore`、处理器注册表类、
   以及 `Goal` / `Rubric` / `Verdict` 的持久化契约**先私有**（`_WITHHELD`），M12 再定。切点名、Store Protocol、Flag
   key、`HistoryKind` 落盘取值变更即破坏性变更。
3. **落盘与外发一律先过 `Redactor`，在写入之前、截断之前（§12.3），收口在内核一处。** 产物登记只记路径 / 版本
   元数据，不落产物正文。Rubric / Goal / Verdict 的文本（含用户原话、产物摘录、裁决理由）**落盘时**脱敏（store、
   trace），**不在注入历史时改写模型看到的指令**（发给模型的请求是脱敏的唯一例外，§12.3 / 评审 M7）；写入面只收
   `Redacted*` 类型来强制。锚点引文比对对脱敏不敏感（两侧都取脱敏后文本再比）。每条新落盘 / 外发点进 AST 守卫。
4. **前缀缓存纪律（spec §5.2）。** Goal / Rubric / Verdict 注入**历史**不进 SP；经内核私有接缝注入（仿
   `_attach_recall`），用署名历史块（`syndica.kind ∈ {goal, rubric, verdict}` + 幂等键）**只在新增 / 变更时重注**。
   Rubric 变更走**追加替代块**（幂等键带 Rubric 集合摘要、新块写明替代哪一份、被替代的旧块不进保护集合），不靠
   rebaseline；禁止 `{cwd}` 一类随轮变量混进这些块。
5. **压缩保护 Goal 与全部生效 Rubric（spec §8.8 不变量 3、#64）。** 加 `HistoryKind.GOAL / RUBRIC / VERDICT`；
   `compaction._protected_indices` 保护 Goal 块与所有 `active` Rubric 块；有 Goal 块时 P17 的「第一条真实 user 消息」
   代理退役（避免 Goal 块顶替真实任务消息）。这是 M6 不变量的兑现，**不在「明确不做」里**。
6. **验收器失败 fail-open，但显式标 `unverified`（spec §10 / §17 #29 / #45）。** 裁决状态**由内核从 per-rubric 结论
   推导**，不采信 LLM 自报的 `status`：任一 checkable 条带证据 `unmet` → `block`；还有未确认 checkable → `partial`；
   checkable 全 `satisfied` → `pass`；**没有 active checkable 条、或验收器自身异常 → `unverified`**（记
   `unverified_cause`）。`judgment` 条的 `RubricOutcome` 一律强制 `needs_human`，不论验收器报什么，`needs_human`
   **不触发重试**但由 Verdict 带出来。四值 / 两类 / 两态 / `RubricOutcome` / `AnchorSource` 枚举的成员→取值表整张
   断言相等（防等长别名把 `unverified` 静默变成 `pass`，AGENTS 变异纪律）。
7. **锚点规则是防「验收方发明需求」的唯一闸（spec §7.6）。** 每条 Rubric 带**非空锚点链** `anchors: tuple[Anchor, ...]`；
   牙齿是**能重新打开**：定位可解析、`quote` 确实出现在该位置、文件锚点钉到具体版本——不是只查「有没有锚点」。
   RubricsBuilder **只看「被要求了什么」、看不到「产出了什么」**，由它的受限读接口在内核侧保证。被锚点规则拒掉的
   候选记 WARNING（`record.args` 带主体 / 拒绝条数 / 原因），并有「合法锚点不报」的反向用例。
8. **伴生 Agent 隔离（AGENTS「作用在错主体」一等变异轴）。** 伴生是**不进注册表**的内核 Agent 实例（编排工具
   `SendMessage / QueryAgent / KillAgent` 寻址不到），由 Module 用绑定在主 Agent**对象**上的闭包构造（不按 `agent_id`
   查）；工具白名单只 `Read / Grep / Glob`，不经 Module 工具工厂、**不挂验收插件**（防递归验收验收器）；Portal 是
   主 Agent 的那一份隔离副本；显式装宿主守卫插件（git 写拦截、私有目录、danger）；各有独立 `max_turns`。用例：两个
   主 Agent 各带伴生、A 的 verifier 只看得到 A 的轨迹与 A 的副本（基数 2，同一 Runtime 内连做三轮）。
9. **处理器冲突确定可解（spec §7.2）。** `ArtifactHandler.handles: tuple[tuple[str, str], ...]`（`(kind, mime)`，
   允许 `'*'`）；全序精度 `(k, m)` > `(k, '*')` > `('*', m)` > `('*', '*')`；同一精度重复注册 Runtime 构造时
   `ConfigError`（三件套点名 kind / mime / 两个处理器的 `module+qualname`），在 Module 回滚语义之内。
10. **产物 `id` 跨版本稳定、`version` 不透明。** `id` 只由规范化路径（加隔离作用域）派生，`producer` 逐版本记；内核
    只对 version 做相等比较与**按登记顺序**排序（git SHA 不可排序），不解析其结构；同一 `(id, version)` 重复登记幂等。
11. **面向调用方的错误三件套**：期望 / 实际 / 下一步。工具返回给模型的错误同理。
12. **Agent（含伴生）不执行 git 写命令。** 验收只读工作区证据与版本 diff；写 / 提交由宿主在人选择之后做
    （spec §12、硬约束 9）。新库目录（`.syndica/artifacts`、`.syndica/rubrics`）进文件工具私有目录——**`cli/host.py`
    `_PRIVATE` 与 `danger.py` `_HOST_RECORDS` 两份名单同步加，并补一条断言两份相等的用例**（现无此断言，评审 B5）。

## 公开契约（发布即承诺）

> 下面是**目标形状**，按阶段冻结。执行中若需调整，先改本节 + 决策日志，Store 签名偏离 spec §4.4 必须同步改 spec。

### 产物模型（§7.2；`ArtifactRef` + `ContextBlock.artifacts` M5 已有）

- `ArtifactRef`（**已存在**，`context.py`）：`id` / `path` / `kind` / `mime` / `version` / `producer` /
  `is_deliverable`。字段不改；登记语义：`id` 由路径（+ 隔离作用域）派生、跨版本不变，`producer` 逐版本。
- `ArtifactReader`（新，kernel）：绑定主 Agent 的 Portal，`read(ref) -> bytes | str`（按指定 version 读内容），供
  处理器的 `validate` / `semantic_diff` 拿字节——它们只有 ref、而 Portal 每个隔离副本一份（评审 H5）。
- `ArtifactHandler`（Protocol）：`handles: tuple[tuple[str, str], ...]`（§7.2 + 评审 H6）；`preview(ref, reader) ->
  Preview`；`semantic_diff(a, b, reader) -> Diff`；`validate(ref, reader) -> list[Violation]`。处理器失败（抛出）由
  内核按 §10 降级：`validate` 抛 → 记「L1 跳过」（`record.args`），**不当成零违规**；`preview` / `diff` 抛 → 无预览 /
  退回二进制 diff，不阻塞。
- `Violation`（kernel dataclass）：`rule` / `message` / `anchor?`（三件套风格）。`Preview` / `Diff` 字段见执行期。
- `ArtifactStore`（Protocol，**对齐 spec §4.4**）：`register(ref) -> None`（按 `id` 归一、追加新 version、同
  `(id, version)` 幂等）；`get(id) -> ArtifactRef | None`；`versions_of(id) -> list[ArtifactRef]`（**登记顺序**）；
  `list(*, kind=None, producer=None, deliverable_only=False) -> list[ArtifactRef]`。内存 + 文件实现 +
  `ArtifactStoreContract`（跨 producer 同路径 → 同 id 两 version；登记顺序排序用 3 个非自然序 version 串钉；交付物
  过滤；同一 id 并发登记三个不同 version、三个都在且顺序即完成顺序，CAS 基数 3）。
- 交付物标记：`ArtifactRef.is_deliverable` 由 `Deliver` 工具置；`note` 随**交付记录**存（`ArtifactStore` 增
  `deliverables() -> list[DeliverableRecord{ id, kind, note }]` 或存进 trace，执行期定，评审 H1：`ArtifactRef` 无
  `note` 字段）。
- 处理器注册表 `ArtifactHandlers`（**私有**）：`register(handler)`（§7.2 冲突解析）、`for_(ref) -> ArtifactHandler`
  （匹配不到回退 `generic`）。基础 `kind` 常量表与 `generic` 处理器在 kernel，**取值与 `tools/local.py` 对齐**。

### 交付物追踪（§7.4，**内核做**，评审 H3）

- 隐式：工具执行器在 `POST_TOOL_USE` 之后把 `ToolResult.artifacts`（写 / 编辑工具已填）`register` 进 `ArtifactStore`
  （Runtime 持有它时），再由内核触发 `ARTIFACT_REGISTERED`。不依赖验收 Module。
- 显式：`Deliver(path, kind, note)`（**内核内置工具**，#79）：路径没登记过先按版本层当前版本登记再标记；不存在 /
  工作区外 → 三件套错误交回模型；`kind` 与路由到的处理器冲突时的处置见决策 M8。Bash 生成的文件经 `Deliver` 显式登记。

### Goal / Rubric / Anchor / Verdict（§7.5 / §7.6；四值与 judgment 语义在内核）

- `Goal`（kernel dataclass，唯一权威）：`intent: str`；`anchors: tuple[Anchor, ...]`。来源见决策 H10（CLI `--goal` /
  宿主 API / 无则从第一条 user 消息派生）；变更即重新投影，重新投影**保留已确认的反馈 Rubric**。
- `Anchor`（kernel dataclass）：`source: AnchorSource`（`user_message` / `file` / `artifact`）；`locator`
  （`msg:<stable-id>` / `spec.md:12` / `report.md#section-4`）；`quote: str`。user 块给稳定定位（注入时写
  `extra['syndica.msg_id']`，压缩后不漂移，评审 H10）。
- `Rubric`（kernel dataclass）：`id`（重新投影间稳定）；`statement`；`kind: RubricKind`（`checkable` / `judgment`）；
  `anchors: tuple[Anchor, ...]`（**非空**，每条可重新打开，否则铸造处拒）；`mandatory: bool`（进度只数强制条，M8
  用）；`status: RubricStatus`（`active` / `proposed`）；`trust`（= 投影输入里最严，评审 H9）。
- `RubricOutcome`（kernel）：`rubric_id` + `kind ∈ {satisfied, unmet, needs_human}` + 证据锚点。`judgment` 条恒
  `needs_human`（内核强制）。
- `Verdict`（kernel dataclass）：`status: VerdictStatus`（**四值**，**内核从 per-rubric 推导**，不收 LLM 自报）；
  `outcomes: tuple[RubricOutcome, ...]`；`needs_human: tuple[str, ...]`；`reason`；`unverified_cause: str | None`
  （fail-open / 无 active checkable 时填）；`provenance`（主 Agent 轨迹 + 验收器读到内容的最严信任，评审 H9）。
- `RubricStore`（Protocol，**私有**，§8.2 独立于对话存储）：方法全带 `scope`（会话 id，评审 H2）：
  `put_goal(scope, RedactedGoal)` / `get_goal(scope)`；`put_rubrics(scope, Redacted…)` / `rubrics(scope, *,
  include_proposed=False)`；`propose(scope, RedactedRubric)` / `activate(scope, id)`（§7.7）。内存 + 文件实现 + 契约
  （先私有）。写入面只收 `RedactedGoal` / `RedactedRubric`（仿 `session_redaction`）。

### 内核新增切点（spec §5.4 切点表同步改）

- `ARTIFACT_REGISTERED`（OBSERVABLE）：内核在产物登记 / 变更后触发；验收 Module 挂 L1。
- `COMPLETION_PROPOSED`（INTERCEPTABLE，评审 H4）：**Agent 判定完成时**（§5.1 第 12 步「无工具调用」处、在 `_finish`
  快照**之前**）触发。契约：
  - **已处理槽位** = `modified['verdict']`（一个 `Verdict`）；`skip` / `result` 报 `ContractViolation`。
  - 内核据 verdict：`pass` / `unverified` → `COMPLETED`；`partial` / `block` → **内核**追加一个署名 `VERDICT` 反馈块
    （hook 不能写轨迹，B-19），按各自重试上限（`block` / `partial` 分开）再做一轮。
  - **fail-open**：验收器抛 `Exception` 由 Module 内部兜成 `unverified` verdict；`CancelledError` 照常上抛（abort →
    `ABORTED`，不得变成 `unverified` 的 `COMPLETED`）；验收器超时用 `asyncio.timeout`（不用 `wait_for`，AGENTS）。
  - **触发范围**：只有带 Goal 的 Agent、且交付物 / Rubric 自上次裁决以来变过时才跑（省成本，§8.4）。
  - **终态**：重写中撞 `MAX_TURNS` 或重试用完 → 最终 verdict = 最后一次裁决（`block` / `partial`），**绝不 `pass`**；
    重试计数按 Agent × run。`Delegate` 出去的子 Agent 的结果带上 verdict（父 Agent 读 `_finish` 快照那一刻）。

### 验收 Runtime Module 的 Flag（§5.5，值域 `bool|int|str`，key 不带点）

- `acceptance_rubrics`（bool，默认 off）：开工前投影 Rubric。
- `acceptance_output`（bool，默认 off）：L2。`acceptance_output_retries`（int，`minimum=0`，默认 1）。
- `acceptance_outcome`（bool，默认 off）：L3。`acceptance_outcome_block_retries`（int，`minimum=0`，默认 2）/
  `acceptance_outcome_partial_retries`（int，`minimum=0`，默认 1）。重试 `0` 的语义写进 Flag 文档；拒 bool 交
  `FlagDeclaration`（确认数值检查前先拒 bool）。
- `acceptance_feedback`（bool，默认 off）：§7.7。
- `acceptance_verifier_timeout`（int 秒）/ `acceptance_verifier_max_turns`（int）：伴生独立预算 / 超时（评审 M5）。
